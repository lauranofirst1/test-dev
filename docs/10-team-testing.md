# 팀원 테스트 안내

**받자마자 화면을 보고, 무엇이 잘못됐는지 말할 수 있게 하는 것**이 이 문서의 목적입니다.
빈 화면에서는 아무것도 판단할 수 없어서, 계정 하나와 **안이 채워진 축제 하나**를
명령 한 번으로 만들어 두었습니다.

---

## 0. 저장소 받기 — 포크해서 씁니다

원본에 직접 밀지 않습니다. **각자 포크해서 자기 저장소에서 작업하고, 다 되면
PR 로 보냅니다.** 실수로 남의 작업 위에 밀어 버리는 일이 구조적으로 안 생기고,
누가 무엇을 고쳤는지도 PR 하나로 남습니다.

1. <https://github.com/lauranofirst1/test-dev> 에서 오른쪽 위 **Fork** 를 누릅니다.
2. 포크한 **자기 저장소**를 클론합니다.

```bash
git clone https://github.com/{내아이디}/test-dev.git
cd test-dev

# 원본을 upstream 으로 걸어 둔다 — 나중에 최신 코드를 당겨오는 통로다
git remote add upstream https://github.com/lauranofirst1/test-dev.git

# 작업 브랜치로 옮긴다 — 테스트도 수정도 여기서 한다
git fetch upstream
git checkout -b test upstream/test
```

이후 최신 코드를 받을 때는 `git pull upstream test` 입니다.
(`git pull` 만 치면 자기 포크를 봅니다.)

고친 것을 보낼 때:

```bash
git push origin test        # 자기 포크로 올린다
```

GitHub 이 띄워 주는 **Compare & pull request** 를 누르고, **받는 쪽 브랜치를
`test` 로** 맞춰 주세요. `main` 이 기본값으로 잡히는데, `main` 은 확인이 끝난
것만 모으는 자리라 바로 열면 안 됩니다.

## 1. 5분 안에 화면 보기

환경 준비(PostgreSQL · 가상환경 · npm)를 아직 안 했다면 [README 의 개발 환경 준비](../README.md#개발-환경-준비)를
먼저 한 번만 하세요. 그 다음은 이 세 줄입니다.

```bash
./dev.sh                                                    # 서버 두 개를 띄운다

# 다른 터미널에서
cd apps/api && ./.venv/bin/python scripts/seed_test_account.py
```

스크립트가 **접근 코드와 현장 화면 주소를 그대로 찍어 줍니다.** 그 출력을 창에 남겨 두세요.

브라우저에서 <http://localhost:5173> 을 열고 로그인합니다.

| | |
|---|---|
| 아이디 | `test@test.com` |
| 비밀번호 | `123456test!` |

> ⚠ **이 계정은 개발·테스트 DB 전용입니다.** 이 비밀번호는 가입 화면으로는 만들 수
> 없습니다 — 정책이 "이메일 아이디가 비밀번호에 들어 있으면 거절" 인데 `test` 가
> 들어 있기 때문입니다. 정한 자격증명을 그대로 쓰려고 시드 스크립트가 해시를 직접
> 넣습니다. 실제 운영 DB 에는 절대 돌리지 마세요.

## 2. 무엇이 들어 있나

축제 하나(`제9회 Hallym SW Week (테스트)`)가 **오늘이 이틀째인 진행 중** 상태로 만들어집니다.
지난 것도 남은 것도 있어야 대시보드와 리포트가 둘 다 볼 것이 생기기 때문입니다.

| 영역 | 데이터 | 이 데이터로 확인하는 것 |
|---|---|---|
| 부스 | 6개(스캔 방식 혼합) · 미션 8개 · 완료 100건 | 최근 30분에 47건이 몰려 있어 **AI 체험존이 51% 집중** 판정을 받습니다 |
| 참여자 | 72명(학번 있음) | 교내 행사라 `identity_mode = student_id` 입니다 |
| 특강 | 2개 | 어제 특강은 48명이 찍었는데 **37명만 인정**됩니다 — 첫 체크인만 찍고 나간 11명 |
| 전시 | 작품 6 · 심사 항목 4 · 심사위원 3 · 투표 66표 | 심사 1위와 관객 1위가 **일부러 어긋나** 있습니다 |
| 그 밖 | 경품 4종 · 공지 2건 · 스탬프판 2×3 · KPI 목표 3개 | |

숫자는 고정된 난수 씨로 만들어집니다. **다시 돌려도 같은 화면**이 나오므로,
어제와 다르면 그것은 코드가 바뀐 것입니다.

## 3. 콘솔에서 볼 것 (운영자 화면)

로그인하면 워크스페이스 → 축제 카드 → 개요로 들어갑니다. 화면마다 "이러면 정상"
한 줄씩만 적습니다. **다르면 그것이 버그입니다.**

| 메뉴 | 주소 | 이러면 정상 |
|---|---|---|
| 현황 | `/festivals/23` | 남은 일과 각 영역 진행 상태가 표로 보입니다 |
| 오늘 | `/festivals/23/dashboard` | AI 체험존이 **집중**, 나머지는 여유. 재배치 확인 요청 카드가 한 장 뜹니다 |
| 특강 출결 | `/festivals/23/lectures` | 어제 특강 `찍은 사람 48 / 출석 인정 37`. 오늘 특강은 체크인이 열려 있습니다 |
| 전시 심사 | `/festivals/23/exhibits` | 작품 6개, 시상 집계에 **심사위원 수 불균등** 경고. 순위가 심사·관객 혼합으로 정해집니다 |
| 부스 · 미션 | `/festivals/23/booths` | 부스 6개(확인 방식 혼합) · 조각 보드 · **경품 탭에 상품 4종과 당첨 확률** |
| 리포트 | `/festivals/23/report` | 목표 대비 실제 |
| 사전 진단 | `/festivals/23/diagnosis` | 관광 데이터를 실호출합니다 — **인증키가 없으면 여기만 안 돕니다** |
| 스태프 (설정) | `/festivals/23/staff` | 발급된 6명. **여기서 코드를 재발급하면 아래 고정 코드가 무효가 됩니다** |
| 경품 수령대 | `/festivals/23/claim` | 당첨된 참여 코드를 찾아 수령을 찍는 화면 |

`23` 자리는 시드 스크립트가 찍어 준 축제 ID 입니다. 다시 채울 때마다 바뀝니다.

## 4. 현장 화면 (역할별)

운영자·심사위원·부스 담당자·학생은 **서로 다른 화면**을 씁니다. 콘솔에서 링크로
열 수 있고, 접근 코드는 테스트 계정에서만 아래처럼 고정해 두었습니다.

| 코드 | 누구 | 무엇을 하는가 |
|---|---|---|
| `SWEEK2` | 현장 운영 | 콘솔과 같은 권한 |
| `BSTAF2` | AI 체험존 담당 | 자기 부스만 지급 (`/booth/festivals/:id`) |
| `BSTAF3` | 메이커존 담당 | 위와 같음 |
| `JUDGE2` `JUDGE3` `JUDGE4` | 심사위원 3명 | 심사표에서 점수 매기기 (`/festivals/:id/judging`) |

로그인 주소는 시드 출력에 그대로 찍혀 있습니다 — `http://localhost:5173/staff/login?f=23&s=53`.

> **콘솔을 열어 둔 채로 심사위원으로 로그인해도 됩니다.** 기관 세션과 스태프 세션은
> 서로 다른 쿠키를 쓰므로 한 브라우저에 함께 삽니다. 예전에는 나중에 로그인한 쪽이
> 앞의 세션을 덮어써서, 콘솔이 멀쩡해 보이는데 저장만 "이 작업은 기획자·운영자만 할
> 수 있습니다" 로 막혔습니다. 그게 다시 보이면 회귀입니다.
>
> 단, **로그아웃은 두 세션을 함께 지웁니다.** 공용 태블릿에서 한쪽만 남으면
> "로그아웃했는데 들어가진다" 가 되기 때문입니다.

부스에 띄우는 회전 QR: `/festivals/:id/booths/:boothId/qr`
강의실 스크린(체크인 QR): `/festivals/:id/lectures/:sessionId/checkin/:checkpointId`

## 5. 관객(학생) 화면

로그인하지 않습니다. 축제 링크로 바로 들어갑니다.

| 화면 | 주소 |
|---|---|
| 참여 · 스탬프판 | `/join/23` |
| 부스 QR 스캔 | `/join/23/scan` |
| 내 특강 출결 | `/join/23/lectures` |
| 체크인 | `/join/23/checkin` |
| 전시 관람 · 투표 | `/join/23/exhibition` |

이 축제는 학번을 받는 설정이라 참여할 때 **학번을 묻습니다**. 참여 코드는
브라우저 `localStorage` 에 남으므로, 다른 학생인 척하려면 시크릿 창을 쓰세요.

공결 확인서는 계정 없이 열리는 화면입니다 — `/verify/:id/:code`.

## 6. 이 제품이 실제로 풀려는 문제 세 가지

기능이 도는지보다 **이 세 가지가 실제로 막히는지**를 봐 주세요. 작년 행사에서
실제로 일어난 일들입니다.

1. **투표 부정** — 스티커를 여러 장 붙이던 것이 "참여 코드 여러 개 받기" 로
   그대로 옮겨올 수 있습니다. 시크릿 창으로 코드를 새로 받아 같은 작품에 또
   투표해 보세요. 학번이 같으면 막혀야 합니다.
2. **출튀** — 특강이 공결을 주기 때문에 찍고 나갑니다. 체크인을 두 번 여는 것이
   대응책입니다. 첫 번째만 찍은 학생이 **인정되지 않는지** 확인하세요(시드에 11명 들어 있습니다).
3. **전시 심사** — 여러 작품 · 여러 항목 · 가중치 · 포스터. 집계가 근거 없이
   숫자만 내놓으면 이의가 들어왔을 때 답할 수 없습니다. 항목별 평균과 심사위원
   수가 함께 보이는지, 한쪽 점수만으로 낸 최종에 그렇다고 적혀 있는지 보세요.

## 7. 데이터를 다시 채우거나 비우기

```bash
cd apps/api

# 처음부터 다시 (테스트 축제만 지우고 새로 만든다 — 축제 ID 가 바뀐다)
./.venv/bin/python scripts/seed_test_account.py --reset

# 현장 참여만 비우기 (부스·미션·보드는 남는다)
./.venv/bin/python scripts/reset_participation.py {축제ID} --yes

# 최근 참여만 더 만들기 (대시보드용)
./.venv/bin/python scripts/seed_traffic.py {축제ID}
```

`--reset` 없이 다시 돌리면 **아무것도 지우지 않습니다.** 테스트하다 만들어 둔 것을
날리지 않기 위해서입니다.

## 8. 버그를 알릴 때

한 줄이라도 아래 네 가지가 있으면 재현할 수 있습니다. 없으면 대부분 재현되지 않습니다.

1. **어느 화면** — 주소 그대로 (`/festivals/23/exhibits`)
2. **무엇을 했는가** — 눌렀다/입력했다/새로고침했다
3. **무엇을 기대했고 무엇이 나왔는가**
4. **스크린샷** — 화면 전체. 잘린 스크린샷은 정렬 문제를 감춥니다

서버 오류라면 `./dev.sh` 를 띄운 터미널의 마지막 30줄을 함께 붙여 주세요.

## 9. 자주 막히는 곳

| 증상 | 원인과 해결 |
|---|---|
| 로그인했는데 계속 로그인 화면으로 튄다 | 이전 버전의 세션 쿠키가 남아 있습니다. 로그아웃을 한 번 누르거나 사이트 데이터를 지우고 다시 로그인하세요 |
| 저장만 "기획자·운영자만 할 수 있습니다" 로 막힌다 | 세션 분리 이전의 회귀입니다. **버그로 알려 주세요** |
| `apps/api/.venv 가 없습니다` | README 의 3번(백엔드)을 안 한 것입니다 |
| `기관이 없습니다` | 시드 스크립트를 안 돌렸거나 다른 DB 를 보고 있습니다 |
| 포트가 이미 쓰이고 있다 | `API_PORT=8001 WEB_PORT=5174 ./dev.sh` |
| 휴대폰으로 QR 을 찍고 싶다 | `WEB_HOST=1 ./dev.sh` — 같은 와이파이에서 접속 |

테스트를 직접 돌려 보려면:

```bash
cd apps/api && ./.venv/bin/python -m pytest -q      # 인증키 없이 돕니다
cd apps/web && npx tsc --noEmit                     # 프론트엔드 타입 검사
```
