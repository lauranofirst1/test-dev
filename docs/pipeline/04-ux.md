# 04 — UX 설계

색·폰트는 다루지 않습니다(`05-ui.md` 몫). 여기서는 구조와 흐름만 정합니다.

## 1. 정보구조

```
FestaFlow
├─ 기획자 영역 (계정 로그인, 기관 스코프)
│  ├─ SCR-1  기획자 워크스페이스        /planner
│  ├─ SCR-2  새 축제 생성               /festivals/new
│  ├─ SCR-3  축제 기획 수정             /festivals/{id}/edit
│  └─ SCR-13 사후 결과보고서            /festivals/{id}/report
│
├─ 운영 영역 (축제별 접근 코드)
│  ├─ SCR-5  스태프 로그인              /staff/login?f=&s=
│  ├─ SCR-6  운영 대시보드              /admin/festivals/{id}/dashboard
│  │   ├─ SCR-7  부스·미션 관리          (탭)
│  │   ├─ SCR-8  스탬프 보드 설정        (탭)
│  │   └─ SCR-4  스태프 관리             (탭)
│  └─ SCR-9  부스 지급 화면             /booth/festivals/{id}
│
└─ 관객 영역 (익명 코드 + 디바이스 시크릿)
   ├─ SCR-10 참여 화면                  /join/{id}
   ├─ SCR-11 조각 보드                  /join/{id}/stamp-board
   └─ SCR-12 참여 복구                  /join/{id}/recover
```

**세 영역은 서로 네비게이션을 공유하지 않습니다.** 기획자는 사이드 네비,
운영자는 탭, 관객은 단일 화면 + 하단 고정 버튼입니다.
현장에서 부스관리자가 실수로 기획 화면에 들어가는 일이 없어야 합니다.

| SCR | 화면 | 만족하는 US |
|---|---|---|
| SCR-1 | 기획자 워크스페이스 | US-1, US-4 |
| SCR-2 | 새 축제 생성 | US-2 |
| SCR-3 | 축제 기획 수정 | US-3 |
| SCR-4 | 스태프 관리 | US-5 |
| SCR-5 | 스태프 로그인 | US-6 |
| SCR-6 | 운영 대시보드 | US-17, US-18 |
| SCR-7 | 부스·미션 관리 | US-7, US-8, US-9 |
| SCR-8 | 스탬프 보드 설정 | US-14 |
| SCR-9 | 부스 지급 화면 | US-12, US-13 |
| SCR-10 | 관객 참여 화면 | US-10, US-16 |
| SCR-11 | 조각 보드 | US-15 |
| SCR-12 | 참여 복구 | US-11 |
| SCR-13 | 결과보고서 | US-19, US-20 |

## 2. 핵심 유저 플로우

### 플로우 A — 축제를 등록하고 현장을 준비한다 (기획자·운영자)

```
SCR-1 워크스페이스
  │ [새 축제] 클릭
  ▼
SCR-2 생성 폼 ──검증 실패──▶ 필드별 오류 표시, 폼 유지
  │ 저장 성공
  ▼
생성 완료 화면 ── operator_access_code 1회 노출 (복사 유도)
  │ [운영안 구성하기]
  ▼
SCR-6 대시보드 → SCR-7 부스·미션 탭
  │ 부스 추가 (첫 미션 동시)
  ▼
SCR-4 스태프 관리 → 부스별 초대 QR·코드 발급 → 인쇄
  ▼
현장 준비 완료
```

### 플로우 B — 현장에서 스탬프를 지급한다 (부스관리자)

```
초대 QR 스캔 → SCR-5 로그인 화면
  │ 6자리 코드 입력 ──5회 실패──▶ 10분 잠금
  ▼
SCR-9 지급 화면 (내 부스 고정)
  │ 관객 QR 스캔 ──카메라 불가──▶ 수동 코드 입력 폴백
  ▼
미션 선택 → [지급]
  │
  ├─ 온라인 ──▶ 즉시 결과 (조각 공개 애니메이션)
  │              └─ 중복 ──▶ "이미 지급됨" + 기존 이력 표시
  │              └─ 타 부스 미션 ──▶ 409 오류 안내
  │
  └─ 오프라인 ──▶ 로컬 큐 적재, "대기 N건" 배지
                    │ 네트워크 복구
                    ▼
                  순차 동기화 → 성공/실패 건수 토스트
```

### 플로우 C — 관객이 조각을 모은다

```
현수막 QR 스캔
  ▼
SCR-10 참여 화면
  │ 최초 진입: 코드 자동 발급 + 뒷 4자리 입력 안내(선택, 건너뛰기 가능)
  │ 재방문: localStorage 재사용
  │ 저장된 코드 없음 + 복구 원함 ──▶ SCR-12 복구
  ▼
내 QR 표시 → 부스에서 스태프에게 보여줌
  ▼
3초 폴링이 새 조각 감지 ──▶ 3.5초 강조 표시
  ▼
SCR-11 조각 보드 → 9/9 완성 → 완성 카드
```

### 플로우 D — 결과보고서를 낸다 (기획자)

```
SCR-1 워크스페이스 → 축제 카드 [성과 리포트]
  ▼
SCR-13 리포트
  │ 참여 0건 ──▶ 빈 상태 + 데이터 수집 개선안 (오류 아님)
  │ 실측 방문객 없음 ──▶ 참여 규모만, 참여율 미표시
  ▼
[PDF 내보내기] → 제출
```

## 3. 화면별 와이어프레임

### SCR-1 기획자 워크스페이스

```
┌────────────────────────────────────────────────────────┐
│ [로고]  춘천시문화재단          [＋ 새 축제]  [계정 ▾] │  ← 기관명이 항상 보임
├────────────────────────────────────────────────────────┤
│ ┌ 최근 축제 요약 ──────────────────────────────────┐  │  1순위
│ │ 춘천 가을 먹거리 축제        [준비중]             │  │
│ │ 강원 춘천 · 공지천  10.10–12                      │  │
│ │ 예상 18,000명 · 예산 2.4억 · 미션 12개            │  │
│ │ [진단]  [운영 관리]  [성과 리포트]                │  │
│ └───────────────────────────────────────────────────┘  │
│                                                        │
│ 전체 축제 (5)                                          │  2순위
│ ┌──────────┐ ┌──────────┐ ┌──────────┐                │
│ │ #12 ...  │ │ #11 ...  │ │ #9  ...  │                │
│ │ [진단]   │ │ [진단]   │ │ [진단]   │                │
│ │ [운영]   │ │ [운영]   │ │ [운영]   │                │
│ │ [보관]   │ │ [보관]   │ │ [보관]   │                │
│ └──────────┘ └──────────┘ └──────────┘                │
└────────────────────────────────────────────────────────┘
```

| 상태 | 표시 |
|---|---|
| 로딩 | 카드 스켈레톤 3개. 스피너 단독 금지 |
| 빈 상태 | "첫 축제를 만들어 보세요" + 큰 CTA. 빈 목록 대신 |
| 에러 | "API 실행 여부를 확인하세요" + [다시 시도] |
| 쿼터 초과 | [＋ 새 축제] 비활성 + "요금제 축제 수를 초과했습니다" |

### SCR-2 새 축제 생성

```
┌────────────────────────────────────────────────────────┐
│ ← 뒤로     새 축제 만들기          [샘플 기획안 불러오기]│
├────────────────────────────────────────────────────────┤
│ ①기본 ─ ②목표 ─ ③예산 ─ ④프로그램 ─ ⑤교통 ─ ⑥관광  │  ← progress, 클릭 이동
├────────────────────────────────────────────────────────┤
│ ┌ ① 기본 정보 (필수) ────────────────────────────┐   │
│ │ 축제명 *          [                        ]    │   │
│ │ 지역 *  [        ]  행사 장소 * [          ]    │   │
│ │ 시작일 * [      ]  종료일 * [      ]            │   │
│ │   └ 종료일이 빠르면 필드 아래 즉시 오류         │   │
│ └─────────────────────────────────────────────────┘   │
│ ┌ ② 목표와 방문객 ───────────────────────────────┐   │
│ │ 예상 방문객 * [        ] 명                     │   │
│ │ 총예산 *      [        ] 원                     │   │
│ └─────────────────────────────────────────────────┘   │
│ ...③~⑥ 선택 입력 카드                                │
├────────────────────────────────────────────────────────┤
│                          [임시저장]  [축제 만들기]     │  ← 하단 고정
└────────────────────────────────────────────────────────┘
```

필수 필드는 `*`와 함께 **레이블에 텍스트로도** 표시합니다(색 단독 금지).
숫자 입력에는 단위(명·원·대·개)를 접미로 붙입니다.

| 상태 | 표시 |
|---|---|
| 검증 실패 | 첫 오류 필드로 포커스 이동 + 상단 요약 "2개 항목을 확인하세요" |
| 저장 중 | 버튼 비활성 + 스피너. **중복 제출 불가** |
| 저장 성공 | 전환 화면에 접근 코드 1회 노출 + [복사] + "다시 볼 수 없습니다" 경고 |
| 저장 실패 | 인라인 오류. **입력값은 전부 유지** |

### SCR-6 운영 대시보드

```
┌────────────────────────────────────────────────────────┐
│ 춘천 가을 축제 · 운영          최종 갱신 17:04 [새로고침]│
├────────────────────────────────────────────────────────┤
│ [현황] [부스·미션] [스탬프 보드] [스태프]              │  ← 탭
├────────────────────────────────────────────────────────┤
│ ┌ 총 참여자 ┐ ┌ 총 완료 ┐ ┌ 최근30분 ┐ ┌ 편중 위험 ┐│  1순위 KPI
│ │   412명   │ │ 1,180건 │ │   96건   │ │   1곳     ││
│ └───────────┘ └─────────┘ └──────────┘ └───────────┘│
│                                                        │
│ ┌ 운영 인사이트 ─────────────────────────────────┐    │  2순위 (행동)
│ │ ⚠ 지역상점존 QR 완료가 8%입니다.                │    │
│ │   현장이 실제로 한산한지 확인해 주세요.         │    │
│ │   근거: 최근 30분 96건 중 8건                   │    │
│ │   [확인함]  [해당 없음]  [추가 보상 설정]       │    │
│ └─────────────────────────────────────────────────┘    │
│                                                        │
│ 부스별 최근 30분                                       │  3순위 (세부)
│ 막국수 체험존   ████████████████░░░  49%  [집중 ▮]    │
│ 닭갈비 골목     █████████░░░░░░░░░░  27%  [주의 ▲]    │
│ 지역상점존      ███░░░░░░░░░░░░░░░░   8%  [여유 ■]    │
│                                                        │
│ ⓘ QR 완료 기반 참여 편중 지표입니다. 실제 인원수나    │
│    물리적 밀집도가 아닙니다.                           │
└────────────────────────────────────────────────────────┘
```

| 상태 | 표시 |
|---|---|
| 데이터 부족 | 모든 부스 "데이터 부족" 배지 + "최근 30분 완료 10건 미만" 사유 |
| 추천 없음 | "지금 조치가 필요한 부스가 없습니다" (빈 카드 아님) |
| 폴링 실패 | 상단에 "연결 확인 중" 배지. **기존 데이터는 그대로 유지** |
| 갱신 없음(304) | 화면 변화 없음. 최종 갱신 시각만 업데이트 |

**폴링은 insights만 갱신합니다.** 다른 탭에서 작성 중인 폼은 절대 초기화되지 않습니다.

### SCR-9 부스 지급 화면 (모바일 우선)

```
┌──────────────────────────┐
│ 막국수 체험존   [대기 0건]│  ← 오프라인 큐 상태 상시 표시
│ A구역 3번 · 김운영        │
├──────────────────────────┤
│ ┌ 카메라 뷰 ───────────┐ │  1순위
│ │                      │ │
│ │    [ QR 스캔 영역 ]  │ │
│ │                      │ │
│ └──────────────────────┘ │
│ 또는 코드 직접 입력       │  ← 폴백 항상 노출
│ [FF-________]  [확인]    │
├──────────────────────────┤
│ 미션 선택                 │  2순위
│ ┌──────────────────────┐ │
│ │ 막국수 반죽 체험 100P│ │
│ │              [지급]  │ │
│ └──────────────────────┘ │
├──────────────────────────┤
│ 최근 지급 (8)             │  3순위
│ FF-3A9K… 반죽체험 17:04  │
└──────────────────────────┘
```

| 상태 | 표시 |
|---|---|
| 지급 성공 | 전체 화면 성공 오버레이 1.5초 + 열린 조각 번호. 소리·진동 |
| 이미 지급됨 | "이미 지급된 미션입니다" + 최초 지급 시각. 오류색 아님(실패가 아님) |
| 타 부스 미션 | "이 부스의 미션이 아닙니다" + 해당 부스명 |
| 오프라인 | 상단 배지 "오프라인 · 대기 3건". 지급 버튼은 **계속 동작** |
| 동기화 중 | "3건 전송 중…" → "3건 완료" 토스트 |
| 동기화 실패 | "1건 실패 — 다시 시도" 버튼. 나머지는 완료 처리 |

| 축제 종료 | 미션 목록 대신 완성 카드와 감사 메시지 |

## 4. 반응형

| 화면 | 데스크톱 | 모바일 |
|---|---|---|
| SCR-1 | 3열 카드 그리드 | 1열. 요약 카드는 접어서 핵심 3줄만 |
| SCR-2 | 2열 폼 + 우측 progress | 1열. progress는 상단 가로 스크롤 칩 |
| SCR-6 | KPI 4열 + 부스 표 | KPI 2×2. 부스 표는 가로 스크롤, 이름·비중·상태만 남김 |
| SCR-9 | — | **모바일 전용 설계.** 데스크톱에서는 중앙 420px 고정 |
| SCR-10/11 | — | **모바일 전용.** 데스크톱 접근 시 QR 안내 |
| SCR-13 | 2열 리포트 | 1열. 차트는 가로 스크롤 컨테이너 |

**가로 스크롤은 표·차트 컨테이너 안에서만** 발생합니다. `body`는 절대 가로로 스크롤되지 않습니다.

## 5. 접근성

**키보드 순서** — 모든 화면에서 `건너뛰기 링크 → 주 네비 → 주요 액션 → 본문 → 하단 고정 버튼` 순.
SCR-9 지급 화면은 `코드 입력 → 미션 목록 → 지급 버튼`이 최단 경로여야 하며,
카메라 영역은 탭 순서에서 건너뜁니다(스캔은 마우스·터치 전용 보조 수단).

**포커스** — 모든 인터랙티브 요소에 3px 가시 링. `outline: none` 단독 사용 금지.
모달·오버레이는 포커스를 가두고, 닫히면 **호출한 요소로 되돌립니다.**

**스크린리더가 읽어야 할 것**

| 상황 | 안내 |
|---|---|
| 지급 성공 | `aria-live="assertive"` — "지급 완료. 4번 조각이 열렸습니다. 총 4/9" |
| 오프라인 큐 변화 | `aria-live="polite"` — "대기 3건" |
| 부스 상태 | 색이 아닌 텍스트로 — "막국수 체험존, 집중, 최근 30분 49%" |
| 조각 타일 | `aria-label` — "4번 조각, 열림" / "5번 조각, 잠김" |
| 폼 오류 | 필드와 `aria-describedby`로 연결. 상단 요약에 오류 개수 |
| 진행률 | `role="progressbar"` + `aria-valuenow/min/max` |

**색 단독 금지** — 부스 상태, 미션 완료 여부, 폼 오류는 전부 아이콘 또는 텍스트를 병기합니다.
야외 직사광선에서는 색 구분이 가장 먼저 무너집니다.

**터치 타겟** — 최소 44×44px. SCR-9의 지급 버튼과 SCR-10의 하단 CTA는 56px 이상.
한 손에 먹거리를 들고 조작하는 상황을 기본값으로 둡니다.

**모션** — `prefers-reduced-motion`에서 조각 공개 애니메이션은 즉시 전환으로 대체하되,
**"새 조각이 열렸다"는 사실 자체는 텍스트로 계속 전달**합니다.
