# 03 — PRD

MVP 관문(`02-plan.md`) 범위의 유저스토리와 수용 기준입니다.
상세 도메인 규칙은 `docs/01-product-spec.md`, 데이터 구조는 `docs/02-data-model.md`를 참조합니다.

용어: **기획자**(planner) · **운영관리자**(operator) · **부스관리자**(booth_manager) · **관객**(participant)

## F-16 기관과 테넌시

### US-1 기관 단위 데이터 격리
기획자로서 **다른 기관의 축제가 섞이지 않도록** 내 기관 축제만 보고 싶다.

- **Given** 기관 A에 축제 3건, 기관 B에 축제 2건이 있고 **When** 기관 A 기획자가 축제 목록을 요청하면 **Then** 3건만 반환한다.
- **Given** 기관 A 기획자가 **When** 기관 B의 축제 ID로 상세를 요청하면 **Then** `404`를 반환한다(`403`이 아니다 — 존재 여부도 노출하지 않는다).
- **Given** 기관의 `festival_quota`가 10이고 이미 10건이 있을 때 **When** 새 축제를 만들면 **Then** `402 QUOTA_EXCEEDED`와 현재 요금제를 반환한다.
- **Given** `plan_tier = enterprise`(quota NULL)일 때 **When** 축제를 만들면 **Then** 개수 제한 없이 생성된다.

## F-1 축제 기획 기록

### US-2 축제 생성
기획자로서 **기획서를 구조화된 데이터로 남기기 위해** 축제 기본 정보를 등록하고 싶다.

- **Given** 필수값(축제명·지역·장소·시작일·종료일·예상 방문객·총예산)이 모두 유효할 때 **When** 생성하면 **Then** `201`과 함께 축제·기획상세·기본 스탬프보드·운영자 스태프 코드가 **하나의 트랜잭션**으로 생성된다.
- **Given** 종료일이 시작일보다 빠를 때 **When** 생성하면 **Then** `422`와 필드명 `ends_on`을 반환하고 **아무것도 생성되지 않는다**.
- **Given** 예상 방문객이 0 이하일 때 **When** 생성하면 **Then** `422`를 반환한다.
- **Given** 생성이 성공했을 때 **Then** 응답의 `operator_access_code`는 **이 응답에서만** 평문으로 노출되고 이후 어떤 조회에도 나오지 않는다.
- **Given** 생성 중 스탬프보드 생성이 실패할 때 **Then** 축제도 함께 롤백되어 부분 생성 상태가 남지 않는다.

### US-3 축제 기획 수정
기획자로서 **기획이 바뀔 때마다 반영하기 위해** 등록한 내용을 수정하고 싶다.

- **Given** 축제에 부스·미션·참여 이력이 있을 때 **When** 기획을 수정하면 **Then** `updated_at`만 갱신되고 하위 데이터는 **하나도 변경되지 않는다**.
- **Given** 저장 요청이 처리 중일 때 **When** 사용자가 저장을 다시 누르면 **Then** 버튼이 비활성이라 중복 요청이 발생하지 않는다.
- **Given** 종료일이 시작일보다 빠르게 수정될 때 **When** 저장하면 **Then** 브라우저 검증·폼 검증·API `422`·DB CHECK 네 겹에서 모두 차단된다.

### US-4 축제 목록과 보관
기획자로서 **지난 축제를 잃지 않으면서 목록을 정리하기 위해** 축제를 보관하고 싶다.

- **Given** 축제 5건이 있을 때 **When** 목록을 조회하면 **Then** 생성 시각 내림차순, 동률 시 ID 내림차순으로 정렬된다.
- **Given** 축제를 보관하면 **When** 목록을 다시 조회하면 **Then** 해당 축제가 즉시 사라지고, 참여 이력과 리포트는 **삭제되지 않는다**.
- **Given** 보관된 축제의 리포트 URL로 직접 접근하면 **Then** 데이터는 여전히 조회된다(보관은 숨김이지 파기가 아니다).
- **Given** 축제가 0건일 때 **When** 목록을 열면 **Then** 빈 목록이 아니라 첫 축제 만들기 안내 화면을 보여준다.
- **Given** API 서버에 연결할 수 없을 때 **Then** "API 실행 여부를 확인하세요"라는 오류를 표시한다(무한 로딩 금지).

## F-15 스태프 접근 제어

### US-5 스태프 발급
운영관리자로서 **현장 인력에게 권한을 주기 위해** 스태프를 발급하고 싶다.

- **Given** 운영관리자가 역할과 담당 부스를 지정할 때 **When** 발급하면 **Then** 초대 URL과 6자리 접근 코드를 **1회만** 반환하고, 서버에는 해시만 저장한다.
- **Given** `booth_manager` 역할일 때 **When** `booth_id`를 비우고 발급하면 **Then** `422`를 반환한다.
- **Given** `operator` 역할일 때 **When** `booth_id`를 넣어 발급하면 **Then** 무시하고 NULL로 저장한다.
- **Given** 코드를 분실했을 때 **When** 재발급하면 **Then** 새 코드가 나오고 **기존 코드는 즉시 무효**가 된다.

### US-6 스태프 2단계 로그인
부스관리자로서 **QR 사진이 새어도 안전하도록** QR과 코드 두 단계로 로그인하고 싶다.

- **Given** 초대 QR을 스캔했을 때 **Then** 로그인 화면만 열리고 세션은 발급되지 않는다(QR에 비밀이 없다).
- **Given** 올바른 6자리 코드를 입력할 때 **When** 제출하면 **Then** `staff_id`·`festival_id`·`role`·`booth_id`가 담긴 세션 토큰이 발급된다.
- **Given** 코드를 5회 연속 틀렸을 때 **When** 6번째를 시도하면 **Then** `429`와 함께 10분간 잠긴다.
- **Given** `booth_manager` 토큰으로 **When** 배정되지 않은 부스의 지급을 요청하면 **Then** `403`을 반환한다.

## F-4 부스와 미션

### US-7 부스와 첫 미션 동시 등록
운영관리자로서 **부스만 덩그러니 남는 일이 없도록** 부스와 첫 미션을 함께 만들고 싶다.

- **Given** 부스 정보와 첫 미션을 함께 제출할 때 **When** 저장하면 **Then** 부스를 flush해 ID를 얻고 미션의 `booth_id`를 그 값으로 **강제 설정**한 뒤 한 번에 커밋한다.
- **Given** 클라이언트가 다른 `booth_id`를 보낼 때 **Then** 무시하고 새로 만든 부스 ID로 덮어쓴다.
- **Given** 미션 생성이 실패할 때 **Then** 부스 생성까지 롤백되어 **부스만 남지 않는다**.
- **Given** 같은 축제에 같은 이름의 부스가 있을 때 **When** 저장하면 **Then** `409`를 반환한다(대소문자 무시 비교).

### US-8 부스 수정과 보관
운영관리자로서 **지급 이력을 잃지 않으면서** 부스를 정리하고 싶다.

- **Given** 지급 이력이 있는 부스를 **When** 보관하면 **Then** `archived_at`이 설정되고 이력은 그대로 남는다.
- **Given** 부스를 보관할 때 **Then** 소속 미션은 `booth_id = NULL` 미배정으로 전환되고, 스탬프 타일 배정은 해제된다.
- **Given** 부스를 비활성(`is_active = false`)으로 바꾸면 **Then** 부스관리자 지급 화면의 선택 목록에서 제외된다.
- **Given** 부스가 보관되어도 **When** 사후 리포트를 조회하면 **Then** 그 부스의 과거 완료 수가 `participations.booth_id` 스냅샷으로 그대로 집계된다.

### US-9 미션 관리
운영관리자로서 **참여자가 할 일을 정의하기 위해** 미션을 만들고 고치고 싶다.

- **Given** 다른 축제의 부스 ID를 연결하려 할 때 **When** 저장하면 **Then** `400 MISSION_BOOTH_FESTIVAL_MISMATCH`를 반환한다.
- **Given** 지급 포인트가 0 미만이거나 1,000,000 초과일 때 **Then** `422`를 반환한다.
- **Given** 완료 이력이 있는 미션을 **When** 보관하면 **Then** 이력의 `mission_id`는 유지되고 미션만 목록에서 빠진다.
- **Given** 미션의 포인트를 나중에 바꿔도 **Then** 이미 지급된 `participations.base_points`는 변하지 않는다.

## F-6 · F-7 · F-8 QR 스탬프 참여

### US-10 참여 코드 발급
관객으로서 **설치도 가입도 없이 바로 참여하기 위해** QR을 찍으면 코드를 받고 싶다.

- **Given** 축제 QR로 처음 진입할 때 **When** 참여를 시작하면 **Then** 서버가 `FF-XXXXXXXX` 형식 코드를 축제 내 유일하게 발급하고 `secret`을 함께 1회 반환한다.
- **Given** 같은 브라우저로 재방문할 때 **Then** localStorage의 코드를 재사용하고 새로 발급하지 않는다.
- **Given** `secret` 없이 보드를 조회할 때 **Then** 공개 조각이 없는 기본 보드 상태로 응답한다(타인 진행을 볼 수 없다).
- **Given** 발급 화면에서 휴대폰 뒷 4자리를 입력하지 않을 때 **Then** 참여는 가능하되 "기기를 바꾸면 복구할 수 없습니다"를 그 자리에서 안내한다.

### US-11 기기 변경 복구
관객으로서 **폰을 바꿔도 모은 조각을 잃지 않기 위해** 참여를 복구하고 싶다.

- **Given** 뒷 4자리를 등록했을 때 **When** 새 기기에서 `코드 + 뒷 4자리`를 입력하면 **Then** 새 `secret`을 발급하고 기존 진행이 그대로 보인다.
- **Given** 뒷 4자리를 5회 틀렸을 때 **When** 6번째를 시도하면 **Then** `429 RECOVERY_ATTEMPTS_EXCEEDED`를 반환한다.
- **Given** 복구 정보를 등록하지 않은 코드일 때 **Then** `404 RECOVERY_NOT_AVAILABLE`을 반환한다.
- **Given** 축제가 종료된 뒤 **Then** 복구 해시는 폐기되어 더 이상 복구할 수 없다.

### US-12 부스 스탬프 지급
부스관리자로서 **관객이 스스로 완료하지 못하게 하면서** 현장에서 스탬프를 주고 싶다.

- **Given** 유효한 참여 코드와 내 부스의 활성 미션일 때 **When** 지급하면 **Then** 완료 이력 1건이 생기고 `booth_id`·`base_points`·`bonus_points`·`verified_via`가 지급 시점 값으로 고정 저장된다.
- **Given** 다른 부스의 미션을 지급하려 할 때 **Then** `409 MISSION_NOT_IN_BOOTH`를 반환한다.
- **Given** 비활성 부스나 비활성 미션일 때 **Then** 각각 `409 BOOTH_INACTIVE` / `409 MISSION_INACTIVE`를 반환한다.
- **Given** 같은 참여자·미션으로 다시 지급할 때 **Then** 새 이력을 만들지 않고 `200`에 `was_already_granted: true`와 기존 이력을 반환한다.
- **Given** 조각 공개가 실패할 때 **Then** 완료 이력까지 롤백되어 **미션만 완료되고 조각은 없는 상태가 생기지 않는다**.
- **Given** 관객용 공개 API에는 **Then** 스스로 완료를 만드는 엔드포인트가 존재하지 않는다.

### US-13 오프라인 지급과 동기화
부스관리자로서 **축제장 통신이 끊겨도 운영이 멈추지 않도록** 오프라인에서 지급하고 싶다.

- **Given** 네트워크가 끊긴 상태일 때 **When** 지급 버튼을 누르면 **Then** 로컬 큐에 쌓이고 화면에 "대기 N건"이 표시된다.
- **Given** 큐에 3건이 쌓여 있고 네트워크가 복구될 때 **When** 동기화되면 **Then** 순서대로 전송되고 각 건에 `client_request_id`가 붙는다.
- **Given** 같은 `client_request_id`가 재전송될 때 **Then** `UNIQUE` 제약이 걸려 중복 이력이 생기지 않고 기존 결과를 반환한다.
- **Given** 오프라인 지급이 동기화될 때 **Then** `completed_at`은 `synced_at`이 아니라 **`queued_at`(현장에서 누른 시각)** 으로 기록된다.
- **Given** 큐 5건 중 2건이 실패할 때 **Then** 나머지 3건은 처리되고 실패분만 큐에 남는다.

### US-14 이미지 조각 보드 설정
운영관리자로서 **관객의 수집 진행을 날리지 않으면서** 보드를 설정하고 싶다.

- **Given** 공개 이력이 있는 보드에서 격자·공개방식·지급단위를 바꿀 때 **When** 저장하면 **Then** `409 BOARD_RESET_REQUIRES_CONFIRMATION`과 영향받는 참여자 수를 반환한다.
- **Given** `confirm=true`로 다시 저장할 때 **Then** `version`이 1 올라가고 새 타일이 생기며 **기존 `stamp_reveals`는 삭제되지 않는다**.
- **Given** 이미지 URL이나 완료 문구만 바꿀 때 **Then** 버전이 오르지 않고 진행이 유지된다.
- **Given** 타일 수가 지급 단위 수보다 많을 때(9조각 / 활성 부스 5개) **Then** 저장은 되지만 대시보드에 완성 불가 경고를 상시 표시한다.

### US-15 조각 공개
관객으로서 **모으는 재미를 느끼기 위해** 부스에서 스탬프를 받으면 조각이 열리기를 원한다.

- **Given** 랜덤 공개 보드일 때 **When** 스탬프를 받으면 **Then** 아직 열리지 않은 타일 중 하나가 `secrets.choice`로 선택된다.
- **Given** 부스 지정 보드에서 해당 부스 타일을 이미 받았을 때 **Then** `409 NO_TILE_AVAILABLE`과 "이 부스에 배정된 조각을 이미 받았습니다"를 반환한다.
- **Given** `grant_unit = booth`일 때 **When** 같은 부스에서 두 번째 미션을 완료하면 **Then** 완료는 기록되지만 조각은 추가로 열리지 않는다.
- **Given** 다른 참여자가 같은 보드를 조회할 때 **Then** 각자의 공개 상태가 독립적으로 직렬화된다.

### US-16 관객 참여 화면
관객으로서 **무엇을 더 해야 하는지 알기 위해** 내 진행과 미션 목록을 보고 싶다.

- **Given** 참여 화면을 열 때 **Then** 내 QR, 진행률(4/9), 활성 미션 목록, 활성 부스 안내가 표시된다.
- **Given** 미션이 비활성이지만 내가 이미 완료했을 때 **Then** "완료" 상태로 계속 표시된다(내 이력은 사라지지 않는다).
- **Given** 부스관리자가 스탬프를 지급할 때 **When** 3초 폴링이 갱신되면 **Then** 새 조각이 열렸다는 강조가 3.5초간 표시된다.
- **Given** 네트워크가 끊긴 상태일 때 **Then** 마지막으로 받은 보드 상태를 로컬 캐시에서 보여준다.
- **Given** 화면 어디에도 **Then** 관객이 스스로 완료를 누르는 버튼은 없다.

## F-9 운영 대시보드

### US-17 현장 참여 현황
운영관리자로서 **어느 부스에 몰리는지 알기 위해** 실시간에 가까운 참여 지표를 보고 싶다.

- **Given** 대시보드를 열 때 **Then** 총 참여자·총 완료·최근 30분 완료·편중 위험 부스 수가 표시된다.
- **Given** 10초 폴링이 돌 때 **Then** insights 상태만 갱신되고 **작성 중인 부스·미션 폼은 초기화되지 않는다**.
- **Given** 데이터가 바뀌지 않았을 때 **When** `If-None-Match`로 재요청하면 **Then** `304`를 반환한다.
- **Given** 최근 30분 전체 완료가 10건 미만일 때 **Then** 모든 부스 상태는 `INSUFFICIENT_DATA`이고 화면에 "데이터 부족"이 표시된다.
- **Given** 부스 상태를 표시할 때 **Then** 색만이 아니라 아이콘·상태 텍스트·판정 이유가 함께 표시된다.

### US-18 운영 추천과 확인 기록
운영관리자로서 **편향된 데이터에 휘둘리지 않기 위해** 추천을 지시가 아닌 확인 요청으로 받고 싶다.

- **Given** 한 부스가 최근 30분 40% 이상이고 다른 활성 부스가 15% 이하일 때 **Then** `REDISTRIBUTE` 추천이 "**현장이 실제로 한산한지 확인해 주세요**" 문구로 표시된다.
- **Given** 최근 30분 전체 완료가 10건 미만일 때 **Then** 추천은 빈 배열이고 억지로 만들지 않는다.
- **Given** 모든 활성 부스가 균형일 때 **Then** 추천을 만들지 않는다.
- **Given** 운영자가 "확인함" 또는 "해당 없음"을 누를 때 **Then** `recommendation_feedbacks`에 판정이 기록된다.
- **Given** 비활성 부스일 때 **Then** 집중 출발점과 분산·무참여 대상에서 모두 제외된다.

## F-13 사후 결과보고서

### US-19 결과보고서 생성
기획자로서 **2주 걸리던 보고서를 반나절에 끝내기 위해** 축제 데이터를 자동 집계한 리포트를 받고 싶다.

- **Given** 완료 참여가 있을 때 **When** 리포트를 열면 **Then** 고유 참여자·총 완료·참여자당 평균·참여 발생 미션 비율이 계산된다.
- **Given** 시간대별 집계를 표시할 때 **Then** KST 기준 1시간 버킷으로 묶인다.
- **Given** 부스별 집계를 계산할 때 **Then** 현재 미션의 부스가 아니라 **`participations.booth_id` 스냅샷**을 사용한다.
- **Given** 부스 스냅샷이 해제된 참여가 있을 때 **Then** `unassigned_completions`로 따로 세고 특정 부스에 임의 배정하지 않는다.
- **Given** 완료 순위에 동률이 있을 때 **Then** 같은 순위를 부여한다.
- **Given** 참여 데이터가 0건일 때 **Then** 오류가 아니라 계획 KPI·명시적 빈 상태·데이터 수집 개선안을 반환한다.
- **Given** 실측 방문객이 없을 때 **Then** 참여율을 계산하지 않고 참여 규모만 표시하며, "실제 방문률이 아니다"라는 문구를 함께 반환한다.

### US-20 리포트 내보내기
기획자로서 **지자체에 제출하기 위해** 리포트를 PDF로 내보내고 싶다.

- **Given** 리포트를 PDF로 내보낼 때 **Then** 차트가 벡터로 포함되어 확대해도 깨지지 않는다.
- **Given** 데이터 출처가 있을 때 **Then** 관광 데이터 공급자·기준월과 추정치 구분이 문서에 표기된다.
- **Given** 비어 있는 섹션이 있을 때 **Then** 숨기지 않고 "미작성"으로 표시한다.

## 릴리즈 기준

MVP가 "완료"이려면 아래를 전부 통과해야 합니다.

1. **축제 1건이 등록 → 부스·미션 등록 → 당일 QR 지급 → 결과보고서 PDF 출력까지 끊김 없이 진행**된다
2. US-1 ~ US-20의 수용 기준이 전부 자동 테스트로 존재하고 통과한다
3. 오프라인 시나리오 테스트: 네트워크를 끊고 지급 5건 → 복구 → 중복 0건, `completed_at`이 `queued_at`과 일치
4. 동시성 테스트: 같은 참여자·미션에 동시 요청 20건 → 완료 이력 정확히 1건
5. 권한 테스트: `booth_manager` 토큰으로 타 부스 지급 시도 → 전부 `403`
6. 테넌시 테스트: 기관 A 토큰으로 기관 B 축제 조회 → 전부 `404`
7. 접근성: 자동 검사(axe) 심각 위반 0건, 키보드만으로 지급 화면 전 과정 조작 가능
8. 부하: 완료 10만 건 축제에서 대시보드 p95 < 1s
